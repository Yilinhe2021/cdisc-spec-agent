# SpecForge（中文说明）

面向 CDISC SDTM / ADaM 数据集说明书（spec）的 **多智能体 + RAG** 工具原型，包含一个网页，分两步：

1. **Spec QC**：上传 spec，返回"写错了或写不清楚"的行，按严重程度排序。每条都有评语、建议向 spec 作者提的问题，以及从知识库检索出的依据。可以下载标注后的 xlsx，意见写在每一行旁边。
2. **Build**：上传修改后的 spec 和源数据。Planner 先按依赖关系排序；每个数据集由 Coder 写 Python 程序，在沙箱里运行，Validator 对照 spec 检查。如果提供了参考数据集，Validator 还会做盲态逐格比对。发现程序 bug 时由 Repairer 自动修复。

## 关键设计

- **确定性规则优先**：31 条通用规则。LLM 只判断规则做不到的事：是否写清楚、意图、跨行矛盾。
- **三个专职审阅 agent 并行**：Clarity、Standards（RAG）、Consistency。之后由 **Judge** 做自校验、去重、附上证据，并参考历史反馈校准。
- **反馈记忆**：用户在页面上的接受 / 驳回会被记录下来，用作 few-shot 校准，并降低反复被驳回的同类问题的置信度。
- **混合检索**：BM25 + 向量，用 RRF 融合；具体变量名会映射到通用写法（`AESTDTC` → `--STDTC`）。
- **先编译器、后 LLM**：可识别的派生写法由确定性编译器直接生成代码，字面量原样从 spec 复制、不重新输入。识别不了的行留给 LLM 补全。
- **问题分类**：`BUILD_BUG` 交给修复循环；`SPEC_GAP` 只报告、不猜；`DATA_ISSUE` 是数据本身的问题。
- **离线模式**：没有 API key 时，每个 agent 都有对应的启发式实现，整条流水线、测试和评测都能跑通。

## 数据与合规

- 仓库里所有数据都是合成的（虚构研究 `SYN-001`）。
- 知识库是自己整理的公开常识摘要，不是 CDISC 文档的原文。
- 不包含任何雇主或专有材料。
